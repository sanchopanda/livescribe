# check-tasks — проверить доску и взять задачу

Механику доски (креды, project/view/bucket id, чтение/перенос/комментарии/метки) берём из скилла
**`task-board`**. Одна карточка за вызов. Автономно, без вопросов про саму доску.

## Шаги

1. **Прочитать доску и показать.** Вывести списком **новые** (колонка «Входящие») и
   **доступные** (колонка «Бэклог») карточки — с метками feature/bug. Если в «В работе» уже
   висит незавершённая карточка — сказать об этом (её логично доделать первой, не плодить WIP).

2. **Порекомендовать и СПРОСИТЬ, какую брать.** Дать рекомендацию (какую взять и одна
   строка почему), и **спросить у пользователя, какую задачу взять** — дождаться ответа.
   Не брать задачу в работу, пока пользователь не выбрал.

3. **Взять выбранную.** По ответу пользователя: если это карточка из «Входящие» с сырой
   формулировкой — сначала уточнить содержание (если неоднозначно) и при необходимости
   перенести в «Бэклог»; затем перенести выбранную в **«В работе»**, коммент «Взял в работу».

4. **Сделать по стандартам репозитория** (см. `AGENTS.md`, `docs/CONVENTIONS.md`).
   - Крупная/творческая (новая фича, изменение поведения) → `superpowers:brainstorming`
     → `superpowers:writing-plans` → `superpowers:subagent-driven-development`.
   - Мелкая/однозначная (правка, багфикс) → `implement-task` или напрямую; TDD для логики,
     `superpowers:systematic-debugging` для бага — сначала корневая причина, потом правка.
   - Соблюдать: английские доменные термины, STT только Deepgram, границы монорепо
     (shared/extension/backend/admin), тесты, обновление доков (`backlog.md`, `PROGRESS.md`,
     при смене правил — `KNOWLEDGE.md`).
   - Если по ходу всплыл отдельный дефект — **сразу своя карточка** (`task-board`), даже если
     чинить его в этом проходе не будем.

5. **Завершить.** Когда реализовано и закоммичено в `main` → перенести карточку в
   **«На проверке»** и оставить **краткий комментарий**: что сделано (+ версия/коммит, если
   релиз). **Деплой — только по явной просьбе владельца** (см. скилл `deploy`). После деплоя
   → **«Готово»**.
   Для правок расширения в комментарии отдельно указать, что клиенту нужна перезагрузка
   расширения — бэкенд-деплой её не заменяет.

6. **Доложить:** какую карточку взял, что сделал, где она сейчас, что дальше.

## Не делать
- Не брать больше одной задачи за вызов.
- Не спрашивать про доску («двигать ли карточку?») — двигать самому.
- Не деплоить без явной просьбы.
- Не объявлять сделанным то, что не проверено прогоном (`superpowers:verification-before-completion`).
