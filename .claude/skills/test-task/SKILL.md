# test-task — проверка

Тонкая обёртка. Делегирует `/verify` для сквозной проверки; сам код не чинит — находки
возвращает в `proceed`/`implement-task`.

## Правило флоу (главное)

**Никогда не говори «работает / готово, смотри» только потому, что процесс стартовал или
сборка прошла.** Сначала убедись, что оно РЕАЛЬНО делает то, что должно, и проверяй по
возрастанию: сборка/типы → тесты → реальное поведение (наблюдаемый результат). Если не смог
проверить поведение — честно скажи, что именно проверил, и попроси подтвердить; не выдавай
за «работает».

## Типы / сборка / юнит

```bash
npm run type-check      # гейт: shared build + type-check backend/extension/shared
npm run build           # сборка всех пакетов (extension собирает MAIN-world скрипты)
```
Если менялась логика — прогнать её тесты. (`lint` в проекте сломан — на него не опираться.)

## Поведение (для изменений расширения/backend)

- Использовать навык `/run`, чтобы поднять и прогнать приложение (backend `ws://localhost:3001`,
  extension `dist/` в `chrome://extensions`), либо Chrome DevTools MCP для прогона сценария на
  странице платформы.
- Прогнать **изменённый сценарий** (старт записи, поток транскрипции, смена режима
  mixed/per-track), снять наблюдаемый результат / скриншоты, проверить консоль на ошибки.

## Вывод

- Явный вердикт **PASS/FAIL** с доказательствами (вывод команд, значения, скриншоты).
- Код здесь не чинить.
