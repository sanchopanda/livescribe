# review-task — ревью

Тонкая обёртка. Сначала дефекты через встроенный `/code-review`, затем чек-лист правил репо.

## Чек-лист правил репо

- **Корректность:** логика, крайние случаи, обработка ошибок (доверяем находкам `/code-review`).
- **Термины:** английские доменные идентификаторы в коде; русский — только в UI-тексте/доках.
- **STT:** только Deepgram (не вернулись Vosk/Whisper; см. ADR-0001).
- **Extension:** при новой платформе обновлены `manifest.json` (matches + MAIN-world),
  `vite.config.ts` entry и флаги в `audio-mode-capabilities.ts`.
- **Backend:** сообщения `start`/`audio`/`stop` обработаны согласованно с `packages/shared`.
- **Тесты:** на новую логику есть и зелёные; `npm run type-check` чист.
- **Документация:** обновлены `KNOWLEDGE.md`/спека/ADR, если менялись правила/архитектура.
- **Гигиена:** нет `.env`/секретов/`dist`/`node_modules` в индексе.

## Вывод

- Находки по severity (critical / major / minor).
- Критичные — починить (через `implement-task` + повторный `test-task`) **до** фиксации задачи.
