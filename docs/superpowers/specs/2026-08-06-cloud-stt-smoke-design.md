# Смок-проверка облачных STT: Nemotron 3.5 и GigaAM против nova-3 (дизайн)

Дата: 2026-08-06. Статус: согласован.
Задача бэклога: подготовка к **LS-13 (self-host RU-STT)**.
Основание: `docs/research/2026-07-26-stt-models-parakeet-gigaam.md`,
ADR `docs/decisions/0005-stt-strategy-self-hosted-ru.md`.

## Задача

ADR-0005 зафиксировал плановый переход на RU-STT (GigaAM / Parakeet) и оставил открытыми
вопросы, которые нельзя закрыть чтением: качество русского на **нашем** аудио, латентность
партиалов, стабильность длинных сессий, стоимость. ADR предполагал свой GPU — с тех пор оба
семейства стали доступны **как облачные API**, поэтому проверку можно сделать без GPU-ops:

- **Nemotron 3.5 ASR Streaming 0.6B** — Together AI, `wss://api.together.ai/v1/realtime`,
  модель `nvidia/nemotron-3.5-asr-streaming-0.6b`, 40 локалей включая RU.
- **GigaAM** — через **SaluteSpeech API** Сбера (платформа построена на семействе GigaAM),
  потоковое распознавание по gRPC с промежуточными гипотезами.

Цель этого шага — **смок, а не бенчмарк**: убедиться, что оба облака принимают наш формат
аудио и отдают внятный русский в стриминге, и увидеть порядок латентности. Полноценный WER
с эталонной разметкой — отдельный шаг, если смок зайдёт.

## Ориентиры по цене (на 2026-08)

| Провайдер | Цена | Против nova-3 streaming |
| --- | --- | --- |
| Deepgram nova-3 streaming (сейчас) | $0.0077/мин ≈ $0.46/час (PAYG) | — |
| Together AI, Nemotron streaming | $0.0015–0.0045/мин | в 2–5× дешевле |
| SaluteSpeech (GigaAM) | 100 мин/мес бесплатно, далее ~1,2 ₽/мин ≈ $0.9/час | ~2× дороже; для юрлица порог 15 000 ₽/мес |

Числа Together расходятся между их же страницами — уточнить по факту первого счёта.
Важно: в нашем **per-track** режиме поминутная цена умножается на число дорожек.

## Решение

Одноразовый смок-скрипт в `packages/backend/scripts/stt-smoke/`. Прод не трогаем:
`STTProviderType` остаётся `'deepgram'`, новые адаптеры живут только в скрипте. Если смок
зайдёт — они становятся заготовкой настоящих реализаций `STTProvider` на следующем шаге.

### Компоненты

| Модуль | Ответственность |
| --- | --- |
| `run.ts` | CLI: `--file <wav> --provider deepgram\|nemotron\|salute`. Склеивает feed + провайдера + лог |
| `feed.ts` | «Проигрыватель» WAV: срезает header, нарезает PCM на чанки по 100 мс и отдаёт их в реальном темпе (wall-clock), имитируя живой звонок. **Покрыто тестами** |
| `providers/deepgram.ts` | Тонкая обёртка над существующим `src/stt/deepgram.ts` — эталон для сравнения |
| `providers/nemotron.ts` | WS на Together: Bearer-авторизация, query `model` + `input_audio_format`, аудио событиями `input_audio_buffer.append` (base64) |
| `providers/salute.ts` | OAuth (Basic `client_id:secret` → `/api/v2/oauth`, scope `SALUTE_SPEECH_PERS`) + gRPC-стрим `Recognize` на `smartspeech.sber.ru`; первое сообщение — `RecognitionOptions` (PCM_S16LE, 16000, ru-RU, промежуточные гипотезы) |
| `report.ts` | Три транскрипта side-by-side + метрики латентности + расчёт стоимости прогона |

Все провайдеры пишут **один и тот же** формат событий — `{ ms_from_start, isFinal, text }` в
`out/<recording>-<provider>.jsonl`, плюс плоский `.txt` с финальным текстом. Это и делает
сравнение возможным: различия видны построчно, а не на глаз по разным форматам.

### Данные

Две существующие записи из `packages/backend/recordings`:

- `recording-62a7123a-2026-02-18T08-04-37-722Z.wav` — 1:56 (короткая, для первого прогона);
- `recording-f11102c6-2026-02-18T08-38-22-258Z.wav` — 6:14 (длинная, на стабильность сессии).

Обе уже **PCM s16le / 16 kHz / mono** — ровно то, что просят оба API, перекодирование не нужно.
Третью запись со смешанной RU/EN речью добавляем только если по этим двум результат непонятен.

### Порядок и правило остановки

Сначала **Nemotron доводится до конца**, потом Сбер. Если Сбер упирается в TLS или proto —
откладываем его и возвращаемся отдельно, не задерживая результат по Nemotron.

## Как оцениваем

- **Качество** — глазами по трём транскриптам рядом. Эталонной разметки и WER на этом шаге нет.
- **Латентность** — машинно: время до первого партиала, отставание партиала от позиции в аудио,
  число финалов за прогон.
- **Стабильность** — прошла ли 6-минутная сессия без разрывов и деградации.
- **Стоимость** — арифметика по фактическим минутам прогона.

## Риски

1. **TLS Сбера.** API за российским корневым CA (Минцифры), Node на Linux его не знает и упадёт
   на handshake. Обход: `russian_trusted_root_ca.pem` через `NODE_EXTRA_CA_CERTS` / gRPC
   credentials. Пишется в README скрипта.
2. **proto-файлы Сбера** нужны из их документации. Если не достанем — Сбер помечается
   заблокированным (см. правило остановки выше).
3. **RU в стриминге у Nemotron 3.5.** Проверяется первым же прогоном на короткой записи: может
   потребоваться явный `language`, либо мультиязычность окажется доступна только в batch.
4. **Токен Сбера живёт 30 минут** — на 6-минутную запись хватает одного, refresh не пишем.
5. **Секреты и приватность.** `TOGETHER_API_KEY`, `SALUTE_CLIENT_ID`/`SALUTE_CLIENT_SECRET` — в
   `packages/backend/.env` (в gitignore). `out/` добавляется в gitignore: транскрипты реальных
   звонков в репозиторий не попадают.

## Тестирование

Скрипт по природе — I/O против внешних API, TDD к нему приложим только частично. Тестами
покрывается единственная чистая единица — `feed.ts` (нарезка PCM, границы чанков, тайминги).
Остальное проверяется фактом прогона на реальных записях.

## Чего сознательно не делаем

WER с эталонной разметкой; per-track и 2-канальный режим SaluteSpeech; fal.ai (≈$2.88/час —
дороже nova-3 в ~6×) и Parakeet TDT (batch-ориентирован); интеграцию провайдеров в прод;
прогон в CI.
