# Встроенный WebRTC-зонд для разведки платформ (дизайн)

Дата: 2026-07-31. Статус: согласован (решение по деталям делегировано исполнителю).
Задача бэклога: подготовка к **LS-02 (Teams per-track)**, переиспользуется для **LS-01 (Zoom)**.

## Задача

Чтобы решить, возможен ли per-track-захват на Teams, нужен ответ на три вопроса из живого
звонка:

1. Сколько входящих аудио-потоков отдаёт платформа — один смикшированный или по одному на
   участника (`inbound-rtp` с независимым `audioLevel`).
2. Чем связать трек с участником: есть ли в DOM атрибут со `ssrc`/`trackIdentifier`, как
   `data-ssrc` у Meet.
3. Живёт ли медиа в главном документе или в iframe (от этого зависит `all_frames` у хука).

Сейчас это делается вставкой консольного сниппета руками. Нужен инструмент внутри dev-сборки:
нажал кнопку — получил JSON.

## Ключевое ограничение

Кнопка не может «поставить» зонд: обёртка над `RTCPeerConnection` обязана встать до того, как
страница создаст соединение, то есть на `document_start`. Поэтому зонд ставится автоматически
(пассивно, ничего не перехватывая), а кнопка только собирает и выгружает отчёт.

## Решение

Отдельный MAIN-world скрипт `document_start` на всех поддерживаемых хостах, **только в
dev-флейворе**. Боевые `*-webrtc-tracks-main.ts` (meet/pachca) и `platform-research.ts` не
трогаем: первые критичны для записи, у второго `document_idle` и своя задача (DOM-трекер).

### Компоненты

| Модуль | Мир | Ответственность |
| --- | --- | --- |
| `content/research/webrtc-probe-main.ts` | MAIN, `document_start`, `all_frames` | Обёртка `RTCPeerConnection`; реестр соединений и `track`-событий. По запросу отдаёт дамп + `getStats()`. Ничего не перехватывает и не пишет звук |
| `content/research/probe-bridge.ts` | ISOLATED | Запрос/ответ через `postMessage` с таймаутом; собирает DOM-часть снимка |
| `content/research/report-builder.ts` | ISOLATED, чистые функции | Нормализация статистики, сопоставление трек↔плитка, сборка отчёта. **Покрыто тестами** |
| Секция «🔬 Research (dev)» в виджете | ISOLATED | Кнопки «Собрать снимок» / «Скачать JSON» / «Копировать» + сводка |

### Данные

Снимки **накапливаются**: жмёшь кнопку, пока говорит один участник, потом пока говорит другой.
В каждом снимке есть и `audioLevel` по каждому `ssrc`, и текущий говорящий по DOM — этого
достаточно, чтобы вручную сопоставить трек с человеком, без таймера и мегабайтных логов.

Снимок содержит:

- `page` — url, платформа, `isTopFrame`, число фреймов;
- по каждому фрейму и peer-connection — состояние, число аудио-ресиверов, по каждому
  `inbound-rtp`: `ssrc`, `trackIdentifier`, `mid`, `audioLevel`, `totalAudioEnergy`,
  `packetsReceived`;
- `domSpeaker` — кто говорит по DOM-детектору платформы на момент клика;
- `tiles` — плитки участников (у Teams `[data-cid="calling-participant-stream"]`) с их
  `data-*`/`aria-*`;
- `attributeMatches` — автопоиск атрибутов, чьё значение совпадает со `ssrc`/`trackIdentifier`
  из статистики. Если у Teams есть аналог `data-ssrc` — он найдётся сам.

### Поток данных

```
MAIN (каждый фрейм)                ISOLATED (верхний фрейм)          UI
webrtc-probe-main                  probe-bridge                      виджет
  hook RTCPeerConnection
  ...                    <--- collect ------                    <-- клик
  getStats()             ---- report (в window.top) --->
                                     + DOM-часть
                                     + report-builder ---------> сводка / JSON
```

Запрос `collect` каждый зонд ретранслирует в дочерние фреймы, а ответ шлёт в `window.top`.
Так покрываются вложенные iframe без перебора фреймов из ISOLATED-мира.

### Границы сборки

Скрипт попадает в `rollupOptions.input` и в `content_scripts` только при `BUILD_TARGET=dev`.
В `dist/` (прод) и `dist-store/` его нет вообще — строже, чем у `platform-research`, который
сейчас вырезается только из store. Секция в виджете рендерится по тому же флагу (`__DEV_TOOLS__`).

### Ошибки

| Ситуация | Поведение |
| --- | --- |
| Зашли до звонка, соединений нет | Снимок собирается, `peerConnections: []`, в сводке `PC: 0` |
| MAIN-мир не ответил за 1.5 с | В снимке `bridgeTimeout: true`, а не пустая тишина |
| `getStats()` упал на одном PC | Этот PC помечается `error`, остальные собираются |
| Платформа не распознана | Кнопка работает, `platform: null` — зонд полезен и на неизвестном хосте |

### Тестирование

В `packages/extension` тест-раннера сейчас нет — заводим `vitest` (в backend он уже
используется, версия та же). Покрываем `report-builder.ts`: нормализацию `RTCStatsReport`,
сопоставление атрибутов, сборку отчёта — всё на простых объектах, без jsdom. MAIN-хук, мост и
UI проверяются живым прогоном в звонке Teams: это и есть их приёмка.

## Что вне объёма

Зонд ничего не захватывает и не отправляет на бэкенд. Он не включает per-track на Teams — это
LS-02, и её объём определится по итогам первого отчёта.
