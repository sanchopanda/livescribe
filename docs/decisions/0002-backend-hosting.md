# 0002 — Хостинг бэкенда

Статус: принято (2026-07-22)

## Контекст

Бэкенд livescribe (Fastify + WebSocket, релей аудио в Deepgram) нужно вынести с localhost
на удалённую тачку — под расширение, а затем лендинг и админку (ADR-0003, single-port).
Нагрузка лёгкая: STT и анализ внешние (Deepgram / LLM-API), сам сервер — I/O-bound релей +
раздача SPA + будущий Postgres. Расширение работает на HTTPS-страницах (Meet/Zoom/Teams),
поэтому подключение к бэкенду обязано быть `wss://` (браузер блокирует `ws://` с HTTPS) —
нужен домен и TLS, голого IP недостаточно. Ресёрч провайдеров — в истории; вы уже используете
Yandex Cloud (expeditor на `158.160.x`).

## Решение

- **Провайдер: Yandex Cloud** (тот же аккаунт/биллинг, что expeditor) — RU-регион (латентность,
  оплата в рублях, 152-ФЗ для хранения записей/транскриптов).
- **Отдельная ВМ** под livescribe (не co-locate с expeditor): Ubuntu LTS, 2 vCPU / 4 ГБ /
  ~40 ГБ SSD, публичный (зарезервированный) IP. Изоляция деплоя/логов/рестартов важнее
  экономии одной ВМ.
- **Домен:** регистрируется отдельный домен под продукт; бэкенд — на поддомене
  (напр. `api.<domain>`), лендинг/админка — на основном (ADR-0003, single-port).
- **TLS: Caddy** как reverse-proxy — авто-Let's Encrypt, терминирует HTTPS/WSS, проксирует
  `/ws` (и позже `/api`, статику) на бэкенд.
- **Процесс: systemd**-сервис бэкенда (автоперезапуск), а не tmux.
- **Аудио** — в S3-совместимое объектное хранилище (Yandex Object Storage), не на диск ВМ.
- **Деплой:** скилл `deploy` (rsync исходников → сборка на сервере → рестарт сервиса →
  пост-проверка `wss`), по образцу expeditor. Релиз ≠ деплой.

## Последствия

- (+) Изолированный, предсказуемый прод; RU-латентность и правовая чистота хранения данных.
- (+) Caddy снимает возню с сертификатами (авто-обновление TLS).
- (−) +1 ВМ к расходам (~750–900 ₽/мес) против co-locate.
- Требуется прод-подготовка кода: вынести WS-URL расширения в конфиг (`wss://<domain>/ws`),
  сузить CORS до origin расширения, поправить manifest (host-permissions/CSP).

## Рассмотренные альтернативы

- **Co-locate на ВМ expeditor** — отклонено: связывает два продукта на одной тачке.
- **Selectel / Aeza / Timeweb** — дешевле/сравнимо, но теряется консолидация с уже
  используемым Yandex Cloud.
- **Hetzner (ЕС)** — лучший ценник, но оплата из РФ, латентность к RU и 152-ФЗ делают его
  плохим выбором под основной бэкенд с хранением переговоров.
- **Голый IP без домена** — невозможно: расширение на HTTPS требует `wss://` с валидным TLS.
