# 0003 — Раскладка монорепо и single-port раздача

Статус: принято (2026-07-22)

(ADR-0002 зарезервирован под решение о хостинге бэкенда — оформляется в LS-06.)

## Контекст

К существующему расширению и бэкенду добавляются **лендинг** и **админка** (история и
анализ переговоров). Вопрос: держать их в этом же репозитории или выносить отдельно.
Проект уже монорепо на npm workspaces (`workspaces: ["packages/*"]`) с пакетами
`@livescribe/shared`, `@livescribe/extension`, `@livescribe/backend`. Extension собран на
React + Vite + Tailwind. Целевой хостинг — одна дешёвая ВМ (см. LS-06).

## Решение

**Всё в одной монорепе.** Добавляем два пакета рядом с существующими:

```
packages/
  shared/     # общие типы (+ Session, Transcript, AnalysisResult, API DTO)
  extension/  # MV3 — как есть
  backend/    # Fastify + WS + @fastify/static (раздаёт landing/admin) + Postgres + /api
  landing/    # React + Vite + Tailwind — маркетинговая SPA
  admin/      # React + Vite + Tailwind — история + анализ (за авторизацией)
```

- Раскладка **плоская `packages/*`** (существующая конвенция репо), без `apps/`.
- Стек лендинга и админки — **React + Vite + Tailwind**, как в `extension` (не Radix/CSS
  Modules из expeditor): единообразие внутри livescribe важнее сходства с соседним проектом.
- **Single-port раздача из бэкенда:** Fastify отдаёт `landing` на `/`, `admin` SPA на
  `/admin` (за авторизацией), сохраняет `/ws`, добавляет `/api/*`. Один процесс, одна ВМ.
- **Данные:** Postgres под сессии/транскрипты/анализ (LS-07); аудио — в S3-совместимое
  объектное хранилище, не на диск ВМ.
- Общие доменные типы и API-DTO живут в `packages/shared`.

## Последствия

- (+) Общие типы без кросс-репозиторной синхронизации.
- (+) Один деплой-артефакт на одну дешёвую ВМ; одна версия / CHANGELOG / CI / `proceed`-флоу.
- (−) Бэкенд-процесс совмещает раздачу статики и API — приемлемо для MVP; при росте лендинг
  можно вынести на статику + CDN (обратимо, отдельным решением).

## Рассмотренные альтернативы

- **Отдельные репозитории** для лендинга/админки — отклонено: координационные издержки и
  боль с общими типами без выгоды на текущем этапе.
- **Каталог `apps/` (как в expeditor)** — отклонено: ломает существующую плоскую
  `packages/*`-конвенцию livescribe.
- **Radix + CSS Modules (стек expeditor)** — отклонено: extension уже на Tailwind,
  выбираем единообразие внутри проекта.
- **Лендинг сразу на статике + CDN** — отложено: на MVP проще single-port; вынос остаётся
  дешёвой обратимой опцией.
