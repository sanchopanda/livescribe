# CONVENTIONS — правила ведения документации

Правила именования и структуры документов livescribe. Соблюдать.

## Именование

- Имена файлов и папок: **латиница, `kebab-case`**, без пробелов и кириллицы.
- Текст документов — **на русском**; идентификаторы, поля данных, имена файлов кода —
  **латиницей** (английские доменные термины).
- Спеки фич: `docs/specs/NN-<feature>.md` (напр. `docs/specs/01-zoom-per-track.md`).
- ADR (архитектурные решения): `docs/decisions/NNNN-<decision>.md`
  (напр. `docs/decisions/0001-stt-deepgram-only.md`).
- Задачи бэклога: идентификатор `LS-NN` (LS-01, LS-02, …).

## Где что лежит

- `docs/KNOWLEDGE.md` — живые заметки: архитектура, глоссарий, грабли. Читать в начале
  работы, обновлять по ходу.
- `docs/backlog.md` — список задач (`LS-NN`), сгруппирован по фазам.
- `docs/PROGRESS.md` — курсор состояния: сделано / следующее / задача в работе / блокеры.
- `docs/CONVENTIONS.md` — этот файл.
- `docs/README.md` — карта документации.
- `docs/decisions/` — ADR по типам решений.
- `docs/specs/` — спеки фич.
- `docs/research/`, `docs/guides/` — при необходимости (анализ, гайды).
- `docs/superpowers/specs/`, `docs/superpowers/plans/` — дизайн-спеки и планы реализации
  (навыки brainstorming/writing-plans).
- `CHANGELOG.md` (корень) — релиз-ноуты (Keep a Changelog).

## Коммиты

- **Conventional Commits**: `feat`, `fix`, `docs`, `refactor`, `chore`, `test` + скоуп
  (напр. `feat(extension): …`, `refactor(stt): …`).
- Трейлер соавторства в конце сообщения:
  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- Коммитить/пушить — только когда попросил пользователь. Коммит **прямо в `main`**
  (практика репо); ветка — только когда нужна изоляция.
- Секреты, `.env`, `dist`, `node_modules` — не коммитить.

## Принцип «доки = зеркало реальности»

На каждой **логической точке** (завершённая задача, конец рабочей сессии) — прежде чем
браться за новое — привести в актуальное состояние `docs/backlog.md` и `docs/PROGRESS.md`,
а при изменении доменной модели/архитектуры — `docs/KNOWLEDGE.md` и соответствующую
спеку/ADR. Истина статуса задачи = состояние git (коммит в `main`).
